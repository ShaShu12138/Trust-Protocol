# Trust Protocol — 五天可玩版本规格

> 最新第一天规则：以 [DAY_01_DESIGN.md](DAY_01_DESIGN.md) 的线性版本为准。必须点击链接触发警方，信息在故事开始前已泄露，官网核验后标注邮件即结束。此前第一天自由调查、转账补救、任意结束及 v1 存档描述已被替换；当前使用 v2 存档，28 项测试通过。

日期：2026-10-26。状态：设计方案，尚未实现、尚未试玩验证。

本次任务是把五天方向落实为可以开发和验收的游戏规则，不把写完文档当作游戏完成。依据同项目对话「分析ING实习生要求」、现有 GAME_DESIGN / FIVE_DAY_CAMPAIGN / DAY_01_DESIGN 文档，以及当前 Mail、来电、桌面实现。

本规格细化原有五天结构；发生冲突时，后续五天版本以本规格为准。旧文档的“当前实现”仍是历史/代码状态说明。明确调整：取消必经教程；保留第一天警方打断但继续到自主调查；拒绝来电不再无限重拨；八个跨日标记的精确定义以下文为准。这些是本轮提出的设计决定，不冒充此前用户已经逐项确认的要求。

用户后续明确要求：第一天每位玩家都必须经历一次警方打断。第一天本身承担剧情式教学，通过催促、诱导和及时拦截建立“这个环境可能欺骗你”的认识；不增加独立教程关。以下触发细节是对这项要求的实现设计。

## 1. 玩家身份、目标与乐趣

玩家是一名在家处理工作和生活事务的普通人，使用自己的虚构电脑。Maya 是熟识的同事；Civic 是工作平台；Nova 是银行；Canal Energy 是正常服务商。无需新职业模拟或人物养成。

表面目标：连续五天把该做的事办完。真正的挑战：谁在要求我做什么、这个渠道是否可信、执行后会改变什么。

核心乐趣来自三件事：发现跨窗口的不一致；自己选择核验路径；看到昨天暴露的信息今天被利用。假消息也可以语法正确、知道真姓名；真消息也可以催促、包含真实异常。不能依靠画风猜答案。

目标体验 30–40 分钟，需试玩校准。每一天只有一个主要事件、一个真实次要任务、一到两条可忽略背景消息。五天共享操作，不新增五套小游戏。

## 2. 核心循环与玩家动词

收到请求 → 看清要求的操作 → 通过独立来源核对 → 执行、拒绝或暂缓 → 检查后果 → 必要时止损 → 日终回顾。

| 操作 | 实际交互 | 记录与限制 |
|---|---|---|
| 检查 | 展开发件地址、查看页面地址/收款方/银行通知 | 打开应用不等于读到证据；只记录具体内容操作 |
| 核验 | 从预置可信书签、银行应用或原有联系人主动联系 | 保留来源；从邮件提供的号码回拨不算独立核验 |
| 执行 | 提交模拟资料、确认固定付款、批准请求、完成工作任务 | 明确列出对象和影响，再由玩家确认；不输入真实资料 |
| 拒绝 | 拒绝请求、挂断、举报指定事项 | 拒绝不自动等于已查明真相；举报要指定对象 |
| 恢复 | 取消待处理操作、冻结受影响支付能力、撤销会话、官方报告 | 必须作用于具体风险；不能一个按钮抹除所有错误 |
| 暂缓 | 将事项留到日终 | 不创造无限待办队列；日终统一说明未处理影响 |

不加入“这是诈骗/这是正常”的答题按钮。事件结果由操作及其顺序计算。真实任务未完成有具体不便，但合理拒绝未知请求不被羞辱或直接判错。

### 信任如何判定

- 预置 Nova 书签、Nova 应用和故事开始前已有的 Maya 联系人是本作明确建立的信任起点。书签说明其为此前保存的入口。
- Browser 搜索只访问本地编写页面；搜索结果第一条不天然可信。初版只支持机构名/固定关键词及明确的无结果反馈，不做任意互联网搜索。
- 身份核验必须由可信来源的实际回复确认。仅看到两个网址不同、银行里没有通知，都只是线索，不单独证明真假。
- 知道名字、金额、以前的事件，不等于可信。警方、银行等称呼仅标注“对方自称”，直到独立核验。
- 不自动弹出“找到关键证据”。用可重开的通信/交易历史支持比较；日终才解释证据的意义。不另建证据板应用。

## 3. 共用流程与时间规则

开始页（语言、开始/继续、本地存档说明）→ 第一天空桌面与突然来电 → 自由处理 → 结束今天 → 日终回顾 → 下一天简短日期/任务说明 → 第五天回顾 → 全程总结。

没有强制教程。帮助入口按需说明如何打开应用、查看来源和结束今天，不指出哪封是假。第一次开场不弹任务清单盖住来电；当日事项可随时从任务栏查看，名称只写请求，例如“处理登录提醒”。

- 无真实倒计时、无根据阅读速度扣钱。压力通过对白和多个事项并存产生。
- 除第一天开场链外，每天最多一次预定来电；玩家主动回拨不限。第一天最多两个不同来电者。
- 第一天挂断后保留约三秒重拨一次的戏剧节奏；再次拒绝后转为可查看的未接记录，不继续抢焦点。挂断后随时可主动核验。
- 通话期间可操作其他应用；拨出新电话先结束当前通话。暂停、日终和离开页面时取消重拨计时。
- “结束今天”一直可找到。仍在通话时可选择挂断并继续；未处理主事件/真实任务分别提醒，不剧透真假。取消确认不改变任何状态。
- 确认结束后未处理事项记为 ignored，主动暂缓记为 deferred；两者均按该日的未完成后果结算，不自动滚成第六天。
- 主事件状态与结果分开：resolved 可以是安全处理，也可以是做出了危险操作；在进入日终前仍可补救，更新结果。

### 交易及恢复的统一规则

所有金额是固定的虚构场景数据，不做自由金额/真实账户输入。交易状态只有 pending / settled / cancelled；不可重复结算。

危险批准产生 pending 项，并在银行内可见。当天结束时，未取消的 pending 项结算为 settled。关闭窗口、挂断、举报本身不取消交易。只有银行里针对该项的取消/保护操作才阻止结算；官方客服可引导，但不代玩家点击。

冻结阻止新的非授权支付并取消对应风险的 pending 项；已经 settled 的损失不自动退款。恢复后风险可以解除，曾经泄露信息的历史不会清零。合法付款被冻结时显示原因，可在官方完成核验和恢复支付能力后重试；因此冻结有不便但不会锁死剧情。

## 4. 五天具体内容

### Day 1 — 谁先告诉了你答案？

**主事件：**陌生银行来电要求点击“新设备确认”邮件。保留用户指定的空桌面、号码来电、循环催促和警方“等一下！！！”的打断。警方打断是每位玩家都会经历的必经剧情，不是只奖励或惩罚某种操作的分支。第一天先建立环境认知，后续日子逐步练习辨别与核验。

**真实任务：**查看 Canal Energy 本月账单，在其此前保存的服务页面确认已自动扣款；无需再支付。背景：Civic 周报。

1. 接听后可边通话边开邮件。查看发件地址可见与 Nova 可信书签不同的域名。
2. 优先触发：点击邮件链接打开本地仿冒页，立即替换为警方来电，先完成警示再开放模拟资料提交；单纯点击不泄露资料、不扣钱。
3. 警方说明正在调查相关来电，提醒暂停；不声称能实时监控玩家电脑，不索要任何资料，也不自动完成事件。此时对方身份仍只是一项声称。
4. 通话结束后桌面继续可用。玩家可以沿 Nova 书签/银行内帮助独立回拨，确认没有该审核请求。
5. 兜底触发：尚未触发警方时，首次请求通过可信渠道核验，或首次点击“结束今天”，先触发警方来电，暂存原操作；警示结束后恢复该操作。谨慎玩家听到“等一下，请先不要按来电者的指示操作”，随后肯定其停下来核实的选择，不谎称他点击过链接。不要求玩家犯错才能推进。
6. 在假页面“提交演示资料”才设置 info-exposed，并出现模拟待处理风险操作。官方核验后可取消该项并报告。

**必经节点的完成规则：**警方来电只呈现一次，取消原诈骗电话重拨；完整接听警示即完成。若拒接或中途挂断，将尚未读到的核心警示作为该次来电的留言显示，玩家确认后完成，不再次强制响铃。未完成警示不能提交日终结算；这项剧情门槛与可忽略的调查任务分开。来电已触发、警示已完成、待恢复操作属于第一天可保存的剧情状态，不新增跨日标记。刷新恢复未完成警示，不重复开场或漏掉节点。仅一直闲置不触发自动跳日；任何离开第一天的路径都经过该节点。

**安全：**可信支持否认请求，玩家拒绝/举报，无提交。**危险：**提交后未取消，日终记录泄露及待处理操作结算。**恢复：**提交后取消风险并报告，避免结算但保留泄露历史。**忽略：**无损失、不算完成核验。

跨日：info-exposed；bank-alerted。次日骗子可引用已泄露细节；报告过则有合法跟进。警方打断只承担叙事节奏，不能成为系统保证“点击以后总有人救”的规则。

### Day 2 — 是熟人的名字，不一定是熟人

**主事件：**“Maya 换了号码”邮件要求垫付 €180，提供新收款人。

**真实任务：**真正的 Maya 要求确认明天项目会议的时间；从原有联系人通话后可完成。背景：普通团队通知。两项不相互依赖才能出现。

线索：新号码不是原有号码；收款人不同；若 Day 1 泄露，对方提到昨日银行风波。该细节提高说服力，不能改变身份判定。

关键操作：从原有 Maya 联系人回拨，真 Maya 否认借款并确认会议。玩家也可按假请求在 Bank 批准固定 €180；此时进入 pending。

安全：独立联系并拒绝假付款。危险：批准且日终未取消。恢复：批准后联系真 Maya，再在 Bank 取消。忽略：不损失钱；若同时错过真实会议确认，次日出现错过安排的通知，不追加支线。

跨日：contact-compromised 表示“已向冒用熟人身份的渠道提交付款/敏感信息”，不表示真实 Maya 账号必然被入侵；social-verified 表示完成原有渠道核验。仅接听或阅读不设置 compromised。

### Day 3 — 真实的银行界面，也能执行错误的指令

**主事件：**自称 Nova 安全部门的来电要求在真正 Bank 应用批准 €900“安全转移”。银行界面真实，收款操作危险。

**真实任务：**确认一笔自己订阅的 €12 服务费用；通过 Bank 交易详情识别，避免误报。背景：普通消费通知。

线索：对方要求保密、不挂断；批准页清楚显示陌生收款人而非安全验证。Day 1 泄露时引用个人细节；bank-alerted 为真时冒充“接手你之前的举报”。

安全：挂断，从可信入口回拨，官方否认安全账户转移，拒绝该请求。危险：批准 €900，日终结算。恢复：批准后在 Bank 取消并通过官方渠道撤销相关授权；若已限制支付，真实订阅显示待恢复而非凭空扣第二次。

跨日：account-at-risk 表示本次未撤销的危险授权；official-channel-established 表示主动完成官方回拨。既往付款损失保留在交易记录中，不靠布尔值表示。

### Day 4 — 两件急事，只有一件需要你登录

**主事件：**工作共享文件邮件让玩家登录 Civic 的仿冒页面。

**真实任务：**在此前保存的 Civic 工作站确认自己的项目交付时间。背景：Canal 服务公告和普通团队邮件。没有新工作软件，页面均由 Browser 渲染。

线索：原有工作站没有对应共享文件；地址不同；通过原有 Maya 联系人可确认没有发送邀请。contact-compromised 为真时邀请提到 Day 2 的付款；否则使用泛化项目标题。social-verified 为真时真 Maya 的回应承接此前核验经历。

安全：可信工作站/原有联系人确认后举报假邀请，并完成真实交付确认。危险：在假页面提交演示凭据，产生工作会话暴露。恢复：从可信工作站撤销外部会话，并向原有工作联系人报告。举报而未撤销不算恢复完成。

跨日：work-access-exposed 记录历史暴露，不能通过恢复清除；work-incident-reported 在官方报告完成时设置。会话是否撤销记录在当天动作/结果中，不再添加第九个布尔标记。

### Day 5 — 有真的问题，不代表他给的办法是真的

**主事件：**Bank 出现真实异常尝试，同时自称“损失追回专员”的来电要求支付 €250 处理费。

即使前四天全安全，也出现被银行拦截的外部尝试通知；不是凭空制造玩家失误或扣款。若 account-at-risk 为真，则是待处理异常授权；过往已经结算的损失只影响背景说明。work-access-exposed 为真且未完成撤销时，骗子引用工作资料；已恢复则显示尝试使用旧会话失败。

**真实任务：**通过官方安全中心处理该异常通知：查看详情、拒绝/撤销相应授权或确认已拦截记录。背景：真实项目回执。

安全：确认异常确实存在，但拒绝付给来电者；自行进入 Bank 安全中心完成处理，必要时官方回拨。危险：批准 €250 处理费而不处理真实异常。恢复：取消处理费 pending 项，并完成官方处置。

结局不能只由是否付费决定：拒付却忽略真实异常，得到“避免新损失，但风险未处理”的回顾；官方处置完成但曾经被骗，也展示恢复价值。第五天不新增长期标记。

## 5. 日终结果、跨日影响与结局

每天主事件固定三类结果文案：verified / exposed / unverified；若 exposed 后完成对应保护，则叠加 recovered 文案，而非建立第四套剧情树。真实任务单独显示 completed / missed。已经提交的历史不因最后点了举报而改写为全程安全。

判定顺序：有危险提交/批准 → exposed（再判定恢复）；否则完成独立核验并处置 → verified；其余 → unverified。第 5 天 verified 还必须完成真实异常处置。

每晚只显示：今天发生的事实、支持判断的实际操作、明天仍存在的影响。没点开的线索不能写成玩家发现；不能声称已曝光但实际上只有打开邮件。不要日终展示下一天正确答案。

八个候选标记沿用旧文档，精确定义以上述每日规则为准。其余历史从已保存的交易、事件结果和动作重建。后续剧情只选择局部文案/通知变体，不为八个布尔组合各写一条故事。

最终展示五天时间线、实际损失/阻止的待处理金额、完成的真实任务、核验与恢复记录。没有综合分数、排行榜或通关失败。

可出现的行为标签不是互斥人格评价：

- “形成核验习惯”：至少三天独立核验，且第 5 天处理真实异常。
- “成功止损”：至少一次危险操作后完成该事件全部恢复步骤。
- “仍有风险待处理”：结束时仍有未撤销危险授权/工作会话或第 5 天异常未处理。
- “真实事务被搁置”：至少两项真实次要任务未完成；不把所有未完成原因都归咎于过度怀疑。

可以同时出现多个标签；全忽略也能走完五天，但时间线会清楚显示缺少核验、任务遗漏及尚未处理的真实异常。损失不阻止后续固定场景付款模拟，避免额外引入余额不足分支。

## 6. 四个应用需要做到哪里

| 应用 | 五天版本必须有 | 本轮不做 |
|---|---|---|
| Mail | 按日消息、发件详情、稳定链接目标、已读、指定事项拒绝/举报 | 写信编辑器、附件系统、邮件协议 |
| Browser | 本地页面、地址显示、可信书签、有限搜索、固定表单/工作任务 | 任意网址、真实联网、自由文本凭据 |
| Bank | 通知、固定交易、确认对象、取消、针对风险冻结/恢复、报告 | 实际账户登录、复杂余额经济、银行后端 |
| Phone | 原有联系人、按来源拨号、未接记录、挂断、对白与固定回应 | 真实拨号、语音识别、AI 生成对白 |

所有看似外部链接都映射本地 pageId/contactId；不直接跳外网。所有模拟表单显示虚构占位内容和“提交演示资料”，禁止收集真实密码。通信号码只作故事标识且不可 tel: 拨出；使用不可能路由的演示标识，避免把未经核实的普通号码当作安全虚构号码。

已有 WindowManager、MailSession、incoming-call、dialogue-panel、翻译与资产继续使用。优先完善内容渲染和状态，不重做桌面皮肤。

## 7. 实现顺序与检查点

这是开发顺序，不是另一次只做 Day 1 的产品缩减；最终交付仍是完整五天。

1. **状态与第一天闭环。** 把故事状态从 game-desktop 分离到无 DOM 的 campaign session/controller；接入 Browser、Bank、Phone 的必要操作。验证第一天安全/危险/恢复/忽略均能到日终。
2. **跨日与本地存档。** 日终确认只应用一次后果，能进入下一天；保存工作期、review 与下一天检查点。验证重复确认、刷新、存储不可用。
3. **第二至第五天内容。** 复用应用和规则，按日添加页面、消息、对白和条件；先完成全部路线，再润色对白。每加一天验证前日影响和无操作跳过路线。
4. **结局和三语。** 时间线来源为动作/结果；中英荷均补齐，非技术界面不暴露 flag/ID。验证切语言不改变结果。
5. **完整试玩和发布验收。** 修阻断问题，录制可复现演示；通过后停止扩展功能。

保留现有 semantic custom events；控制器校验 action 对象是否存在、属于当前日、是否可用，再更新状态。Mail 已存在的 sender-inspected 等事件可接入证据，不另造平行消息总线。

采用 CONTENT_SCHEMA 中最小的 action/condition/effect 子集即可；不先制作通用脚本语言、可视化编辑器或插件框架。新增状态字段必须有当天用途。存档继续遵守 GAME_STATE_AND_SAVE 的一次结算和 localStorage 失败降级规则。

### 必须通过的验收矩阵

| 检查 | 预期 |
|---|---|
| 五天各四条路线（安全、危险、恢复、忽略） | 都能结束当日，效果与交易恰好应用一次 |
| 五天全安全 / 全危险 / 每次恢复 / 全忽略 | 全部到最终时间线；无余额或联系人导致死路 |
| 跳过所有背景邮件 | 不阻挡任何一天 |
| Day 1 点击链接 / 先独立核验 / 直接结束 | 三条路线均恰好触发一次警方打断；警示完成后才能进入日终 |
| Day 1 拒接警方 / 中途挂断 / 警示中刷新 | 剩余警示可经留言完成；不重复响铃、不漏节点、不强迫点可疑链接 |
| pending 在日终前取消 / 仅举报未取消 | 前者不扣款；后者按规则结算 |
| 来源相同的假邮件、假网站、假号码互相印证 | 不计独立核验 |
| Day 1 泄露→Day 2；报告→Day 3；Day 2→Day 4；Day 3/4→Day 5 | 至少一个可见且有依据的后续变化 |
| 在危险行为后、恢复后、review、下一天重载 | 状态一致，信息不复原，钱不重复扣 |
| 非当前日、未知、重复动作 | 拒绝或幂等，无越级/重复奖励 |
| 三语 / 键盘完成核心操作 / 减少动画 | 同样可通关；不要求拖动才能读到关键操作 |
| 损坏存档、未知版本、存储失败 | 可说明原因并重新开始或内存继续，不白屏 |
| 两到三名未读设计文档的玩家试玩 | 记录卡点、用时和误解；不宣称已证明学习效果 |

## 8. 本轮明确不扩展

不增加战斗、自由聊天、后台服务、真实金融 API、全新美术包、额外关卡、账号同步、计时评分或第五个应用。五天不是五倍的系统开发，主要新增量应是经过验证的内容、对白和状态组合。

尚需在实际试玩判断的假设：警方打断是否削弱自主核验；5–8 分钟日长是否成立；玩家能否分辨“已读”与“已处理”。这些以试玩观察修正，不靠加更多剧情掩盖。
