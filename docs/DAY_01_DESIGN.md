# 第一天：大额消费通知

当前实现（2026-10-26），替代此前的设备登录和标记流程。

1. 空桌面，陌生号码 +31 20 794 0148 来电，自称 Nova 银行，声称存在 €1,249 消费。
2. 玩家打开邮件，点击“确认交易”或“取消交易”。这是必经剧情动作，不打开新窗口。
3. 112 来电打断：阻止继续操作，说明此前个人信息泄露，建议独立查证并附理由转发。
4. 玩家自行打开浏览器，搜索 Nova、Nova 银行、银行、bank 等。浏览器具有地址栏、前进、后退、刷新与独立搜索结果页。三条结果中可以进入银行官网，在底部或联系入口查看 service@novabank.nl 和官方发件域名。
5. 也可直接打开银行 App，查看近期及待处理交易；没有对应的大额消费。
6. 邮件中选择“转发给警方”，八个固定理由单选，点击发送。无需先调查，不限制错误理由，不即时判分、不生成举报说明，仅显示已转发。
7. 3.5 秒后警方回电，按所选理由反馈核查结果，继续后结束第一天。

## 理由与回电

- 发件地址不符、链接地址不符、交易信息不符：核查确认对应矛盾。
- 索取密码验证码、要求转账、安装软件、冒充熟人、期限威胁：仍接受举报，但回电说明该理由与本邮件不符。当前邮件没有期限或威胁用语。

## 实现边界

所有搜索、银行页面、交易、转发和电话均在本地运行，没有外部发送或拨号。112 是本游戏的叙事约定，不代表现实来电身份验证机制。游戏界面不显示“虚拟、模拟、例子”说明。

存档使用 trust-protocol.day-one.v3；保留但不读取此前 v2 进度，新版从第一天开场开始。搜索为有限剧情结果，不是互联网搜索。

验证：45 项单元测试通过，生产构建通过。覆盖八种理由均可提交、延迟回电、必经链接、挂断后剧情可继续、存档校验。

邮件发件人地址始终显示，不再提供展开/收起按钮。两个交易按钮共用同一警方来电触发逻辑。
